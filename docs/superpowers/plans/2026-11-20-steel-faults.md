# Steel Plates Faults Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Track work with checkboxes.

**Goal:** Собрать локальное приложение для классификации дефектов, мониторинга сдвига и управляемого дообучения.

**Architecture:** Модули импорта, модели, мониторинга и очереди работают независимо от Streamlit. Операции записи выполняются только по явному действию оператора. Демонстрационные эксперименты воспроизводимы и используют то же ядро, что и приложение.

**Tech Stack:** Python 3.13, Streamlit, scikit-learn, pandas, NumPy, SciPy, Matplotlib, Seaborn, PyMongo для BSON, SQLite, pytest.

**Spec:** [Классификация дефектов стальных листов](../specs/2026-11-20-steel-faults-design.md).

## Global Constraints

- Семь классов UCI, 27 конечных числовых признаков, русскоязычный интерфейс.
- Графики дашборда и аналитического отчёта строятся с помощью Matplotlib и Seaborn и отображаются в Streamlit.
- Источник — локальные исходные файлы. Импорт JSON, CSV и BSON. Выгрузка результатов в CSV.
- Фиксированный источник контрольных данных. Метки тестовой выборки никогда не участвуют в обучении или настройке порогов. Семена экспериментов фиксированы.
- Сдвиг меняет приоритет проверки партии. Для корректного ввода прогноз доступен независимо от статуса мониторинга и разметки.
- Сравнение активного и случайного отбора проводится при одинаковых бюджетах и на одних и тех же отложенных данных. Ставки для оценки экономики задаёт пользователь.

## Review Focus

- Переставленные столбцы дают одинаковый результат во всех трёх форматах; ошибки содержат номер записи и поле (задача 1).
- Один корректный дефект получает прогноз при недостаточном объёме для оценки сдвига (задачи 3 и 6).
- Повторный импорт и повторное подтверждение той же строки не увеличивают обучающую выборку (задача 4).
- Ошибка дообучения сохраняет предыдущую активную версию и ранее подтверждённые метки (задача 4).
- Если целевое качество не достигнуто одним из подходов, отчёт обозначает это и не выводит сумму экономии (задача 5).

## Внутренняя часть

Задачи 1–5 отвечают за данные и расчёты. Их можно запускать и тестировать без браузера. На выходе — прогнозы, метрики, сигналы о сдвиге, очередь на проверку и результаты экспериментов.

### 3. Мониторинг сдвига

**Интерфейсы:** `fit_drift_baseline(reference: pd.DataFrame, validation: pd.DataFrame, seed: int = 42) -> DriftBaseline`, `assess_drift(baseline: DriftBaseline, batch: pd.DataFrame) -> DriftReport`. `DriftReport` содержит статус `insufficient_data`, `stable` или `shift`, оценку сдвига и информативные признаки.

- [ ] Написать тесты на статус для 1–29 записей, обнаружение сильного сдвига нескольких признаков и ранжирование изменившегося признака в синтетическом примере.

- [ ] Использовать расстояние Колмогорова–Смирнова по каждому признаку и максимум расстояний как сигнал партии. Порог брать по 95-му процентилю максимумов на обычных партиях из калибровочных данных. Калибровать по размеру партии с фиксированным семенем (для крупных партий использовать опорный размер, ограниченный объёмом калибровки, и применять его же при оценке).
